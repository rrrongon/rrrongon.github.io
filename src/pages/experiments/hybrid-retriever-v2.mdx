## 1. Benchmark Dataset (`v2.0`)

To benchmark retrieval quality without relying on generic public leaderboards, this project uses a versioned golden dataset (`data/golden_dataset.json`, `v2.0`). It separates the searchable knowledge base (`documents`) from labeled test cases (`queries`), enabling deterministic, repeatable regression testing across retrieval configurations.

### Corpus (22 Technical Documents)

The corpus simulates an ML infrastructure and production operations knowledge base engineered with **hard-negative distractor clusters**—groups of documents that share nearly identical templates and differ only by an error code, exit signal, SKU, or CLI flag:

| Doc IDs | Domain Cluster | Count | Purpose in Evaluation |
| :--- | :--- | :---: | :--- |
| `doc_01` – `doc_03` | LLM Inference & Vector Math | 3 | Tests conceptual phrasing (PagedAttention, continuous batching, L2 normalization). |
| `doc_04` – `doc_09` | Connection Pool Errors (`ERR_4091`–`4096`) | 6 | Hard negatives with identical prefixes (*"Worker node connection pool exhausted..."*) differing only in error code and remediation. |
| `doc_10` – `doc_13` | Container Exit Codes (`EXIT_137`–`255`) | 4 | Hard negatives with identical opening phrasing (*"Container terminated abruptly by host kernel..."*). |
| `doc_14` – `doc_17` | Hardware Parts (`SKU-901A`–`901D`) | 4 | Tests exact alphanumeric SKU discrimination across similar hardware specs. |
| `doc_18` – `doc_20` | vLLM CLI Flags (`--max-*`, `--gpu-*`) | 3 | Tests hyphenated flag retention alongside overlapping GPU memory terms. |
| `doc_21` – `doc_22` | Billing & Eval Operations | 2 | Zero-keyword-overlap paraphrase targets (Terminate Subscription, JSONL offline scoring). |

### Labeled Query Suite (14 Queries)

Each query maps to one ground-truth `expected_doc_id` and is tagged by `category` so aggregate metrics cannot hide localized failure modes:

* **`semantic` (`q01` – `q04`, 4 queries):** Natural-language questions using synonyms and paraphrases with little or no exact word overlap with the target document (e.g., *"How do I stop my yearly membership from auto-renewing?"* $\rightarrow$ `doc_21`). Tests conceptual alignment and asymmetric `query:` / `passage:` prefixes.
* **`exact_id` (`q05` – `q14`, 10 queries):** Troubleshooting and spec lookups containing exact identifiers (`ERR_4094`, `EXIT_139`, `SKU-901B`, `--max-model-len`). Tests whether dense embeddings blur exact tokens inside near-duplicate clusters—and how hybrid search resolves them.

## 2. Evaluation Metrics

Every retrieval configuration returns the top $K = 3$ document IDs per query and is scored deterministically across four metrics:

### 1. Recall@3
* **What it tells us:** Whether the retriever found the correct document anywhere inside the top 3 results (retrieval coverage), regardless of whether it landed at rank #1, #2, or #3.
* **How to compute:** Give `1.0` if `expected_doc_id` is in the top 3 retrieved IDs, and `0.0` otherwise; then take the average across all $N$ queries:

$$\text{Recall@3} = \frac{1}{N} \sum_{i=1}^{N} \mathbf{1}(\text{expected}_i \in \text{top3}_i)$$

* **Simple example (3 queries):**
  * Query A: Expected doc is at Rank #1 $\rightarrow 1.0$
  * Query B: Expected doc is at Rank #3 $\rightarrow 1.0$
  * Query C: Expected doc is at Rank #5 (not in top 3) $\rightarrow 0.0$
  * $\text{Recall@3} = \dfrac{1.0 + 1.0 + 0.0}{3} = \mathbf{0.67}$

### 2. MRR@3 (Mean Reciprocal Rank)
* **What it tells us:** How high the retriever ranks the correct document (ranking precision). Unlike Recall@3, MRR@3 rewards putting the right answer at #1 rather than burying it at #2 or #3.
* **How to compute:** Take $\frac{1}{\text{rank}}$ of the expected document if it appears in the top 3 (`1.0` for #1, `0.50` for #2, `0.33` for #3) or `0.0` if missed, then average across all $N$ queries:

$$\text{MRR@3} = \frac{1}{N} \sum_{i=1}^{N} \text{RR}_i, \quad \text{where } \text{RR}_i = \begin{cases} \dfrac{1}{\text{rank}_i} & \text{if } \text{expected}_i \in \text{top3}_i \\ 0 & \text{otherwise} \end{cases}$$

* **Simple example (same 3 queries):**
  * Query A (Rank #1): $\frac{1}{1} = 1.00$
  * Query B (Rank #3): $\frac{1}{3} = 0.33$
  * Query C (Missed top 3): $0.00$
  * $\text{MRR@3} = \dfrac{1.00 + 0.33 + 0.00}{3} = \mathbf{0.44}$

### 3. Semantic MRR
* **What it tells us:** How well the retriever understands conceptual meaning and paraphrases when exact keywords do not match.
* **How to compute:** Filter the evaluation set to only `category == "semantic"` queries (`q01`–`q04`), then compute MRR@3 on that subset.
* **Simple example (4 semantic queries):**
  * `q01` (Rank #1 $\rightarrow 1.00$), `q02` (Rank #1 $\rightarrow 1.00$), `q03` (Rank #2 $\rightarrow 0.50$), `q04` (Rank #1 $\rightarrow 1.00$)
  * $\text{Semantic MRR} = \dfrac{1.00 + 1.00 + 0.50 + 1.00}{4} = \mathbf{0.88}$

### 4. Exact-ID MRR
* **What it tells us:** How reliably the retriever preserves exact alphanumeric identifiers (error codes, exit signals, SKUs, CLI flags) without confusing them with near-duplicate documents.
* **How to compute:** Filter the evaluation set to only `category == "exact_id"` queries (`q05`–`q14`), then compute MRR@3 on that subset.
* **Simple example (4 exact-ID queries):**
  * `q05` (Rank #1 $\rightarrow 1.00$), `q06` (Missed top 3 $\rightarrow 0.00$), `q07` (Rank #2 $\rightarrow 0.50$), `q08` (Rank #1 $\rightarrow 1.00$)
  * $\text{Exact-ID MRR} = \dfrac{1.00 + 0.00 + 0.50 + 1.00}{4} = \mathbf{0.63}$
